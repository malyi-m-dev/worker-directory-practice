# WorkerDirectory — учёт парка СИМ (класс WORKER)

[![Build and self-test](https://github.com/malyi-m-dev/worker-directory-practice/actions/workflows/kotlin.yml/badge.svg)](https://github.com/malyi-m-dev/worker-directory-practice/actions/workflows/kotlin.yml)

Проект подготовлен в рамках производственной (технологической (проектно-технологической))
практики, кейс-задача № 3, для **ООО «Шеринговые Технологии»** (отдел информационных
технологий, платформа «Юрент», группа МТС). Реализация — на **Kotlin** (JVM).

## Адаптация задания под организацию

Профильная деятельность компании — не HR, а разработка платформы шеринга средств
индивидуальной мобильности (СИМ): электросамокатов, электровелосипедов, павербанков.
Поэтому класс `WORKER` из типового задания перенесён на предметную область самокатного
парка — того актива, вокруг которого построен весь сервис компании, — по прямой аналогии
с исходными полями:

| Поле в типовом задании | Поле в `Worker` | Смысл |
|---|---|---|
| фамилия и инициалы работника | `inventoryNumber` | бортовой (инвентарный) номер единицы парка |
| название занимаемой должности | `vehicleType` | тип/модель транспортного средства |
| зарплата | `bookValue` | балансовая стоимость единицы, руб. |
| год поступления на работу | `commissionedYear` | год ввода в эксплуатацию |
| стаж работы в организации | `getServiceYears()` | срок эксплуатации, лет |

## Что делает программа

- Хранит единицы парка в виде объектов класса `Worker`: бортовой номер, тип ТС,
  балансовая стоимость, год ввода в эксплуатацию.
- Данные вводятся с клавиатуры; объекты складываются в динамическую коллекцию
  `MutableList<Worker>`.
- Пользователь вводит пороговое значение срока эксплуатации (в годах); программа выводит
  бортовые номера единиц парка, чей срок эксплуатации **больше** этого значения (кандидаты
  на списание/замену), либо сообщение об отсутствии таких единиц.
- Класс `Worker` описан в отдельном модуле — файле [`Worker.kt`](./Worker.kt); логика
  ввода/вывода — в [`Program.kt`](./Program.kt).

## Структура репозитория

```
WorkerDirectory/
├── Worker.kt                — класс WORKER (поля, конструкторы, деструктор, методы)
├── Program.kt                — точка входа, ввод/вывод, фильтрация по сроку эксплуатации
├── SelfTests.kt               — самопроверочные тесты (без внешних пакетов)
└── .github/workflows/        — CI: установка Kotlin, сборка и прогон тестов на GitHub Actions
```

## Как собрать и запустить

Требуется установленный компилятор Kotlin (`kotlinc`) и JDK 17+.

```bash
kotlinc Worker.kt Program.kt SelfTests.kt -include-runtime -d app.jar
java -jar app.jar
```

Программа предзаполнит парк демонстрационными единицами (созданными через разные
конструкторы `Worker`), затем предложит добавить свои и запросит пороговое значение
срока эксплуатации.

## Как прогнать тесты

```bash
java -jar app.jar --selftest
```

Тесты проверяют конструкторы (по умолчанию, частичные, полный, копирующий),
методы изменения/отображения полей, расчёт срока эксплуатации и валидацию данных
(отрицательная стоимость отклоняется исключением). При каждом push сборка и тесты
автоматически запускаются в GitHub Actions (см. значок статуса выше либо вкладку
**Actions** репозитория).

## Класс WORKER: краткая сводка по ООП

| Требование             | Реализация в `Worker.kt`                                             |
|-------------------------|------------------------------------------------------------------------|
| Инкапсуляция            | Поля `private`, доступ только через методы `get*`/`set*` с валидацией   |
| Конструктор по умолчанию| `Worker()`                                                              |
| Конструкторы с параметрами | `Worker(номер, тип)`, `Worker(номер, тип, стоимость)`, `Worker(номер, тип, стоимость, год)`, конструктор копирования `Worker(other: Worker)` |
| Деструктор              | `protected fun finalize()` — учебная демонстрация; на JVM управляется сборщиком мусора, для реальных ресурсов используется `AutoCloseable`/`use {}` |
| Методы изменения        | `setInventoryNumber`, `setVehicleType`, `setBookValue`, `setCommissionedYear`, `changeData` |
| Методы отображения      | `getInventoryNumber`, `getVehicleType`, `getBookValue`, `getCommissionedYear`, `display()`, `toString()` |
| Метод по условию задачи | `getServiceYears(asOfYear: Int = текущий год)` — расчёт срока эксплуатации (аналог стажа) |
| Хранение объектов       | `MutableList<Worker>` (динамическая коллекция) в `Program.kt`           |
